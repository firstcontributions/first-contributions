# 🐖 양돈 AI — 농장 진단·설계

> 상용은 기록·탐지까지. 이 프로젝트는 **진단·설계**다 —
> "왜 못 나오는지, 얼마 손해인지, 몇 원인지, 지을 방이 있는지."

**돈방 CCTV 발정 탐지에서 출발했다.** 그런데 국내 202농장 4년치(466행) 실측을
재 보니 손실이 발정에만 있지 않았다. 그래서 범위를 **농장 전체 관리**로 넓혔다
— 발정·임신·분만·돈군흐름·생산비까지 한 줄로 잇는다.
**데이터가 판단을 바꾼 것이지, 처음부터 전체를 노린 게 아니다.**

가장 강한 실측 하나: **국내 상위 10% 농장의 이유후 육성률은 93.9%로 덴마크
문헌치(93.3%)를 이미 따라잡았다.** 격차는 국가가 아니라 **농장 사이**에 있다 —
그래서 고칠 수 있는 문제다.

```
CCTV → [탐지] → [추적/활동] → [행동·자세] → [발정 판정] → [번식 일정] → [돈군흐름] → [손익]
        ─── 인식 ──────────────────────  ── 번식 운영 ──  ─ 농장 설계 ─  ─ 우선순위 ─
```

### 먼저 말하는 한계

- **실농장 실증은 없다.** 데이터 적합성은 실측으로 규명했으나, 수태율 개선을
  현장에서 증명한 바 없다
- **이 서브셋으로는 발정 판정이 안 된다.** 71471 로 카메라·개체를 통제하면
  AUC 0.465 — 무작위다. 원인은 모델이 아니라 **라벨 어휘**(발정 지시 행동이
  주석에 없음)
- **폴리곤은 bbox 보다 낫지 않다.** 정답 폴리곤을 써도 Macro-F1 −0.018.
  10GB 원천과 CPU 14시간을 쓰지 않아도 된다는 결론을 라벨 8MB 로 냈다

부정 결과를 뒤에 숨기지 않는 이유는 [`docs/STATUS.md`](docs/STATUS.md)에 적었다.
**수치의 정본은 그 문서다** — 여기 숫자와 갈리면 그쪽이 맞다.

### 자세 인식 — 병목을 분해하고 개선한 기록

교배사(스톨)는 돼지가 이동하지 못해 활동량 신호가 구조적으로 없다. 남는 건 자세와
그 변화이므로 **자세 정확도가 곧 교배사 발정 판정의 상한**이다. 이전에 보고하던
0.642 는 **누수된 분할**(train1↔train2 가 이미지 3,090장 공유)에서 나온 값이라
폐기했다. 못 본 카메라로 검증하면 0.4 대다. 그 숫자를 셋으로 쪼갰다.

| | 5클래스 acc / MF1 | 발정 3클래스 acc / MF1 |
|---|---|---|
| 다수 클래스만 찍기(기준선) | 0.423 / 0.119 | 0.547 / 0.239 |
| 기하만 (기존) | 0.414 / 0.228 | 0.513 / 0.350 |
| 기하 + 크롭 외형 | 0.435 / 0.226 | 0.553 / 0.371 |
| **기하 + 크롭 + 뷰 정규화** | **0.467 / 0.249** | **0.636 / 0.434** |
| 돈방째 held-out(가장 엄정) | 0.461 / 0.259 | 0.606 / 0.408 |

**1) 정확도만 보면 안 된다.** 기존 기하 전용 모델은 5클래스 0.414 인데 다수 클래스만
찍어도 0.423 이다 — 정확도 기준으로는 기준선보다 못하다. 클래스가 치우쳐 정확도가
신호를 가린다. 판별력은 Macro-F1 에서 드러난다(0.119 → 0.228 → 0.249).

**2) 좌/우 횡와는 bbox 로 구분 불가 — 그런데 그게 병목은 아니었다.** bbox 만
보면 둘 다 옆으로 누운 같은 상자라, 기하 모델은 좌횡와를 좌 157 / 우 210 으로
동전을 던진다. 두 클래스가 전체의 27.8% 이므로 **bbox 모델의 5클래스 상한은
0.861** 이다.

**CNN 으로 재보니 픽셀에는 방향 정보가 있다.** 예측을 좌/우로 한정하면 정확도
**0.699**(동전 0.5) — 즉 "원리상 불가" 가 아니라 **"bbox 로는 불가"** 였다.
그러나 CNN 5클래스는 0.557 로 상한 0.861 에서 한참 아래다. **상한은 병목이
아니었다.**

진짜 병목은 혼동행렬에 있다. 정답이 좌/우인 6,485건 중 **좌/우로 예측한 건
27.1% 뿐**이고, 나머지는 복와 39.4% · 기립 30.3% 로 샌다:

| 정답 클래스 | 재현율 |
|---|---|
| Standing | **89.3%** |
| Sternal_lying | 45.8% |
| Lateral_lying_left | 23.2% |
| Lateral_lying_right | 15.3% |
| Sitting | 11.1% |

**병목은 좌/우 구분이 아니라 "옆으로 누움 vs 엎드림 vs 서있음" 이고**, 그건
못 본 카메라로 일반화하는 문제다. 발정 판정에는 좌우가 의미가 없으므로
(`stall_estrus` 는 기립/기좌/횡와로 뭉친다) **응용 지표는 3클래스**다.

**3) 평가 자체가 불안정했다.** 기존 코드는 뷰 8개 중 마지막 2개만 held-out 으로 썼는데
그 둘이 전체의 42% 였다. 뷰별 leave-one-out(7폴드)으로 바꿨다. 폴드별 정확도가
0.356~0.770 로 흩어지므로 한 번의 임의 분할로 낸 수치는 신뢰할 수 없다.

**개선 수단 두 가지와 그 상호작용.** 크롭 외형(48×48 정규화 후 방향 히스토그램·
실루엣 모멘트 등 60종)이 단독으로 +0.040(3클래스), **뷰 단위 무감독 정규화**는 단독
으로는 오히려 −0.004 인데 둘을 합치면 +0.123 이 된다. 기하 피처는 이미 프레임 상대
값이라 정규화할 여지가 없고, 카메라별 밝기·대비 편차를 안고 있는 건 크롭 쪽이기
때문이다. 뷰 정규화는 그 카메라의 **입력 분포만** 쓰므로 누수가 아니며 현장 절차와
같다(설치 → 녹화 수집 → 통계 산출 → 판정). 다만 단발 이미지 추론에는 쓸 수 없다.

**그래서 발정 판정이 얼마나 좋아지는가.** 자세는 그 자체가 목적이 아니므로 하류로
전파시켜 재야 한다(`stall_estrus.py`, 스톨 200개·시드 20회):

| 자세 3클래스 정확도 | 발정 판정 AUC |
|---|---|
| 1.000 (완벽, 참고) | 0.804 |
| **0.732 (CNN, 캐글 GPU)** | **0.713 ± 0.019** |
| 0.636 (기하+크롭+뷰정규화) | 0.709 ± 0.016 |
| 0.547 (다수 클래스) | 0.699 ± 0.029 |
| 0.513 (기하만) | 0.684 ± 0.028 |

초기 구간(0.513→0.636)은 발정 AUC 를 **+0.025** 올린다. 그런데 **CNN 으로
0.636 → 0.732 를 더 올렸더니 +0.004 에 그쳤다**(0.709 → 0.713) — 시드 표준편차
0.019 안쪽이라 **구별되지 않는다.**

> **자세 개선은 실측이지만, 그게 응용 지표로 넘어오지 않는다는 것도 실측이다.**
> 전파 곡선이 중간에서 평평하고 완벽 자세에서만 튄다. 자세 정확도를 상류
> 목표로 더 밀어붙이는 것은 이 구간에서 효율이 나쁘다 — 남은 격차 0.091 은
> 자세를 거의 완벽하게 만들어야 회수된다.

전파가 1:1 이 아닌 이유는 자세 오차가 시계열 통계(전환율·부동 비율)로 집계되며
일부 상쇄되기 때문이다. 처음엔 스톨 24개·시드 5회로 쟀는데 시드 분산이 커
**순서가 뒤집혔다**(정확도가 낮은 쪽이 AUC 가 높게 나옴) — 표본을 늘려 다시 쟀다.
오류 모형은 균등 추출 단순화이고 실제 혼동은 비대칭(횡와↔기립)이라 어림치다.

## 파이프라인 3축

### ① 관찰 (Observation)
- **탐지**: pig-detection(YOLO) 45,611 bbox, 8개 소스. `build_detection_viewer.py`
- **추적**: IoU + 외형 Re-ID(HSV·gradient 40D + 위치 게이트)로 개체 ID 부여,
  가림에 의한 단편화 46% 감소. `iou_tracker.py`
- **행동 인식**: 기하+모션 → **외형 + 시간윈도우** 조합으로 0.432→**0.516** 개선
  (둘이 상보적: +시간 0.471 / +외형 0.491 / **둘 다 0.516**).
  `model_behavior_appearance.py`, `temporal_features.py`
- **탐지기 자체 학습**: pig-detection 3,743장으로 YOLOv8n 학습(mAP50 0.659) →
  **임의 영상에 바로 적용 가능**. `models/pig_yolo.pt`, `train_pseudo_label.py`
- **활동 분석**: 점유 heatmap·마릿수·활동량 추이. `build_activity_analysis.py`

### ② 판정·진단 (Diagnosis)
- **발정 표준(71471)**: 승가·꼬리세움·기립반사 등 수의학 근거 가중치로 발정 점수화.
  실데이터 발정 정답이 오면 지도학습으로 보정. `aihub_estrus_reference.py`
- **개체별 발정 타임라인**: 추적 ID별 발정 점수 시계열. `build_estrus_timeline.py`
- **번식 문제 진단**: 블랙박스 무발정 확률을 **문제 3종 × 원인 4종**의 실행 구조로
  전환 — 문제 유형 분류 + 원인 귀인 + 개체별 처방. `repro_cause_attribution.py`
  - 문제: 이유후 발정지연 · 무발정 · 미약(둔성)발정
  - 원인: 영양(등지방·사료) · 더위스트레스(THI) · 수퇘지자극 · 사양관리

### ③ 예측 (Prediction)
- **발정 조기경보**: 이유 후 일 단위 발정 준비도 추세를 외삽해 **발정 예상일(D-day)**
  선제 경보 + 정상 WEI(7일) 초과·무발정 조기 포착. `estrus_early_warning.py`
- **CCTV→무발정 융합**: 관찰 신호 + 관리요인 융합 위험 예측 + 처방. `pipeline_gilt.py`

#### 실측 결과 — 이 서브셋으로는 발정 판정이 불가하다 (근거 확보)

세 단계로 엄격도를 높이며 측정했다(`estrus_contrast_eval.py`, 전체 33,600파일에서
조건을 만족하는 7개체·2,492프레임 선별):

| 설계 | 통제 수준 | AUC |
|---|---|---|
| ① 돈방 라벨 + bbox 기하 | 없음 | ~1.00 ← **가짜(카메라 암기)** |
| ② 개체 내 대조 · 행동만 | 카메라 교락 제거 | 0.579 |
| **③ 채널 고정 · 행동만** | **카메라·돈방·개체 전부 통제** | **0.465** |

- `ESTRUS` 라벨은 **개체가 아니라 돈방/카메라 단위**였다(ch1~8 전부 발정,
  ch9~16 전부 비발정). 기하 피처를 쓰면 AUC 1.0 이 나오지만 **못 본 카메라에서는
  0.409 로 무너져** 카메라 암기였음이 드러난다.
- 외음부 라벨(`ANIMAL_ID`+`DATE`, 22,497건·175개체)을 **발정 달력**으로 삼아
  bbox 와 연결해, 같은 개체의 발정일 vs 비발정일 대조를 구성했다
  (`estrus_calendar.py`). 같은 카메라에서 발정 상태만 바뀌는 최상 조건에서도
  **무작위 수준(0.465)**.
- 원인은 모델이 아니라 **라벨 어휘**다. 이 서브셋 행동은 4종
  (`lying·standing·sitting·eating`)뿐이고 **발정 지시 행동(tailing 꼬리세움·
  mounting 승가·기립반사)이 주석에 없다.** 단일 프레임 자세로는 활동량 변화도
  담기지 않는다.

> 이는 실패가 아니라 **데이터 적합성에 대한 실측 근거**다. 검증기는 이런 교락을
> **자동 탐지**해 누수된 AUC 를 보고하지 않는다(`validate_estrus_reference.py`).
> 발정 판정에는 ① 원천 **동영상**(활동량 시계열) ② 발정 지시 행동이 포함된 주석
> ③ 외음부 **이미지 원천** 중 하나가 필요하다. 상세: [`docs/AIHUB.md`](docs/AIHUB.md)

## 국내 실축사 영상 검증 (적용 조건 규명)

직접 학습한 탐지기로 국내 모돈사 영상을 처리해 **어디서 되고 어디서 안 되는지**를

| 조건 | 판정 | 근거 |

## 포지셔닝 — 무엇을 내놓고, 무엇을 안 하는가

**상용 제품과의 대조표를 싣지 않는다.** 각 제품이 무엇을 지원하는지 1차 자료로
확인하지 않았고, 확인하지 않은 것을 "약함 / 없음"으로 적는 순간 이 문서가
지켜 온 실측·계산·가정 구분이 무너진다. 남이 못 한다는 주장 없이도 아래 표는
선다.

### 내놓는 것 — 전부 돌아가는 코드다

### 다루지 않는 영역 — 여기서 기대하면 안 되는 것

- **실농장 실증** 미실시. 데이터 적합성은 실측으로 규명했으나 수태율 개선을
  현장에서 증명한 바 없다
- **하드웨어 제어**(쿨링·급이 자동 연동) 미대상. 처방 **텍스트**까지다
- **모바일 알람 발송** 미구현. 경보 콘솔·푸시는 목업이다
- **ERP·회계 통합** 미대상
- **발정 판정 자체가 미완**이다 — 71471 서브셋으로는 AUC 0.465(무작위).
  아래 「한계와 향후」 참조

### 센서 방식의 맞교환

RFID 이표는 개체 ID 가 결정적으로 읽히고, 영상 Re-ID 는 학습된 매칭이라
여기 측정치가 일관성 0.77 이다. **식별 확실성은 이표가 낫다.** 이쪽의
맞교환 조건은 이표·리더 설치 없이 기존 CCTV 만 쓴다는 것이고, 중소농가
진입장벽을 목표로 한 선택이다.

## 한계와 향후 (정직한 기술)

- **발정 판정 미완(원인 규명됨)**: 71471 [Bbox] 서브셋으로 실측한 결과, 카메라·개체를
  통제하면 AUC 0.465(무작위)로 **이 라벨로는 발정 판정이 불가**함을 확인했다. 발정
  지시 행동이 주석에 없는 것이 원인. → 원천 동영상 또는 외음부 이미지 원천이 필요.
- **행동 인식 0.516**: 미묘 행동(fight·sitting) 혼동은 남음. → 시퀀스(LSTM) 여지.
  방향은 실측으로 확정됐다 — 정지 프레임 피처는 천장(71471 자세 44차원 0.596 ≈
  행동 4종 0.619)이고 **시간 축이 효과**(롤링 윈도우 +0.042, 모션 기반 활동/휴식 0.739).
- **도메인 격차**: 케글은 영국 연구용 우리, 국내 상용 돈방과 차이. 교차-데이터셋
  일반화 ~0.41. → 국내 데이터 파인튜닝 필요.
- **Re-ID 한계**: 고전 외형 Re-ID는 위치 게이트로 오병합을 막았으나 잔여 단편화
  존재. → 메트릭 러닝 여지.

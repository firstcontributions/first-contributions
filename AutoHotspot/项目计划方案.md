# 项目计划方案：用户登录后自动开启 Windows 移动热点

## 1. 项目背景与目标

### 1.1 背景

用户希望安装一次软件，此后在指定 Windows 用户登录后自动开启移动热点，并能够通过标准卸载流程完整清理程序文件和自动启动项。

Windows 移动热点依赖交互式用户会话及该用户的网络配置。因此，本项目所称的“自动开启”是指**用户登录后自动开启**，不是无人登录时在系统启动阶段开启。

### 1.2 目标

- 用户安装一次 `Setup.exe`，此后该用户每次登录 Windows 时自动开启移动热点。
- 后台程序无窗口运行，成功时无需用户操作。
- 网络暂未就绪时自动重试，不阻塞用户登录。
- 登录后延时约 30 秒，再开始热点操作。
- 热点操作开始、成功或失败时发送对应系统通知。
- 失败时静默退出并写入本地日志，便于排查。
- 提供标准卸载功能，卸载后清理程序文件和登录启动快捷方式。
- 交付可安装的 EXE，不依赖外部 PowerShell 脚本。

### 1.3 首版范围

- 支持 Windows 10/11 x64；ARM64 是否支持在原型验证后决定。
- 登录启动快捷方式仅为执行安装的当前 Windows 用户创建。
- 复用该用户在 Windows“移动热点”设置中保存的名称、密码和频段。
- 不在首版中提供热点名称、密码或频段配置界面。
- 不承诺在没有用户登录、企业策略禁止热点或硬件不支持热点时工作。

## 2. 技术方案

### 2.1 核心原理

使用 C#/.NET 调用 Windows Runtime API：

- `NetworkInformation.GetInternetConnectionProfile()` 获取当前 Internet 连接配置。
- `NetworkOperatorTetheringManager.CreateFromConnectionProfile()` 创建热点管理器。
- `StartTetheringAsync()` 异步启动热点。
- 检查 `NetworkOperatorTetheringOperationResult.Status` 和 `AdditionalErrorMessage`，确认热点是否真正启动。

选择 C# 而不是 `ps2exe` 的原因：

- 可以原生使用 `await` 正确等待 WinRT 异步操作。
- 更容易实现结构化错误处理、退出码、重试和日志。
- 避免 PowerShell 5.1 无法直接对 `IAsyncOperation<T>` 调用 `GetAwaiter()` 的问题。
- 更符合独立后台 EXE 的交付形式，也能降低脚本封装程序被安全软件误报的概率。

### 2.2 整体架构

```text
用户 -> Setup.exe（Inno Setup 安装包）
        | 安装时
        +-- 复制 AutoHotspot.exe 到安装目录
        +-- 在当前用户启动目录创建快捷方式
        +-- 安装完成后执行一次验证
        +-- 注册卸载信息
        |
用户登录 -> Windows 启动目录快捷方式 -> AutoHotspot.exe（无窗口、单次运行）
                         +-- 等待约 30 秒
                         +-- 发送“热点正在自启动”通知
                         +-- 轮询等待网络就绪
                         +-- 读取当前热点状态
                         +-- 调用 WinRT API 开启热点
                         +-- 检查结果并写入日志
                         +-- 发送完成或失败通知
                         +-- 退出
```

### 2.3 技术选型

| 环节 | 工具 | 说明 |
|---|---|---|
| 后台程序 | C# / .NET Windows 应用 | 调用 WinRT API，支持异步、重试、日志和退出码 |
| 安装包 | Inno Setup | 复制文件、创建登录启动快捷方式、执行安装验证和卸载清理 |
| 自动启动 | 当前用户启动目录快捷方式 | 当前用户登录时由 Windows Shell 启动，无需管理员权限 |
| 日志 | 文本文件 | 写入 `%LocalAppData%\AutoHotspot\logs`，不得记录热点密码 |

具体 .NET 目标框架和发布方式在原型阶段确定。优先验证 `net8.0-windows`；若采用 self-contained 发布，应评估安装包体积，若采用 framework-dependent 发布，应在安装时检测对应运行时。

## 3. 程序行为设计

### 3.1 启动流程

1. 启动后立即创建本次运行日志。
2. 登录启动模式先等待约 30 秒，`--status-only` 不等待。
3. 发送“热点正在自启动”系统通知。
4. 调用 `GetInternetConnectionProfile()` 检查网络是否就绪。
5. 网络未就绪时每 5 秒重试一次，最长等待 60 秒。
6. 获取连接配置后创建 `NetworkOperatorTetheringManager`。
7. 如果热点已经为 `On`，记录成功，发送“热点自启动完成”通知并退出。
8. 如果热点为 `Off`，调用并等待 `StartTetheringAsync()`。
9. 检查返回状态；成功时发送完成通知并返回退出码 `0`，失败时记录错误、发送失败通知并返回非零退出码。
10. 捕获未处理异常并记录，但不阻塞登录。

### 3.2 日志和隐私

- 默认日志目录：`%LocalAppData%\AutoHotspot\logs`。
- 记录时间、程序版本、执行阶段、热点状态、API 返回状态和必要的错误信息。
- 不记录热点密码、用户凭据或其他敏感信息。
- 设置日志保留上限，例如只保留最近 10 个文件，防止长期增长。
- 安装验证失败时，安装器应提示日志位置；登录自动运行失败时不弹出窗口。

### 3.3 登录启动项

- 在当前用户的 Windows 启动目录创建 `AutoHotspot` 快捷方式。
- 快捷方式目标为安装目录中 `AutoHotspot.exe` 的完整路径。
- 由 Windows Shell 保存和解析目标路径，正确支持包含空格的路径。
- 程序按当前用户普通权限运行，不请求不必要的管理员权限。
- 重复安装或升级时覆盖现有同名快捷方式，不创建重复启动项。

## 5. 关键实现要求

### 5.1 WinRT 调用示意

以下代码仅表示核心流程，实际实现还需加入网络轮询、日志、异常处理和退出码：

```csharp
var profile = NetworkInformation.GetInternetConnectionProfile();
if (profile is null)
{
    return ExitCode.NetworkUnavailable;
}

var manager = NetworkOperatorTetheringManager.CreateFromConnectionProfile(profile);
if (manager.TetheringOperationalState == TetheringOperationalState.On)
{
    return ExitCode.Success;
}

var result = await manager.StartTetheringAsync();
if (result.Status != TetheringOperationStatus.Success)
{
    logger.Error("Start hotspot failed: {Status}; {Message}",
        result.Status,
        result.AdditionalErrorMessage);
    return ExitCode.StartFailed;
}

return ExitCode.Success;
```

具体命名空间、目标框架和 WinRT 引用方式以原型项目实际编译结果为准。

### 5.2 安装器要求

- 使用 Inno Setup 的 `{app}` 或 `{autopf}` 常量，不硬编码安装盘符和 Program Files 路径。
- 使用当前用户安装模式，不要求管理员权限。
- 使用 Inno Setup 的 `[Icons]` 创建当前用户启动目录快捷方式。
- 安装完成后立即执行一次 `AutoHotspot.exe`，根据退出码提示成功或失败。
- 卸载时删除启动快捷方式和程序文件。
- 升级安装时更新程序并覆盖启动快捷方式。

## 6. 风险与应对措施

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 登录时网络尚未就绪 | 本次热点启动失败 | 每 5 秒轮询，最长等待 60 秒；记录超时日志 |
| 无 Internet Connection Profile | 无法创建热点管理器 | 明确退出码和日志，不阻塞用户登录 |
| 网卡或驱动不支持移动热点 | 功能不可用 | 原型阶段检测目标设备；记录 API 返回状态 |
| 用户从未配置过移动热点 | 启动可能失败或配置不符合预期 | 首版要求用户预先在 Windows 设置中确认一次热点配置 |
| 企业组策略禁用热点 | 功能不可用 | 明确列为不支持场景，记录系统返回错误 |
| VPN 或多个网络配置导致选错共享连接 | 热点无网络或启动失败 | 纳入测试；必要时增加配置选择策略 |
| 启动快捷方式创建到错误用户 | 登录后不执行 | 使用 `{userstartup}`，并在安装测试中核对快捷方式位置 |
| 安装路径包含空格 | 启动项无法运行 EXE | 由 Inno Setup 创建 Shell 快捷方式，避免命令行引号歧义 |
| 未签名程序触发 SmartScreen | 用户不信任或安装受阻 | 内部分发先验证；公开分发前采购代码签名证书 |
| 日志无限增长 | 占用磁盘空间 | 限制日志数量和单文件大小 |

`ExecutionPolicy Bypass` 不作为风险应对措施。PowerShell 执行策略不能解决 WinRT 权限、硬件支持、驱动或企业策略问题。

## 7. 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 热点关闭且以太网已连接 | 程序成功开启热点并返回退出码 `0` |
| 热点已经开启 | 程序不重复操作，正常退出 |
| 网络延迟 30 秒就绪 | 程序重试后成功开启热点 |
| 60 秒内没有网络配置 | 程序超时退出并写入明确日志 |
| 无支持热点的无线网卡 | 程序不崩溃，记录明确失败信息 |
| 企业策略禁用热点 | 程序不崩溃，记录 API 返回状态 |
| 安装目录包含空格 | 启动快捷方式可以正常启动程序 |
| 安装完成后立即验证 | 安装器能够根据退出码提示结果 |
| 当前安装用户重新登录 | 热点自动开启 |
| 其他用户登录 | 不自动运行，符合首版当前用户范围 |
| 重复安装或升级 | 不产生重复启动快捷方式 |
| 卸载 | 删除启动快捷方式和程序文件 |
| Windows 10 x64 | 在明确支持的系统版本上通过全部核心用例 |
| Windows 11 x64 | 在明确支持的系统版本上通过全部核心用例 |

## 9. 项目决策门槛

完成 M1 后，根据以下条件决定是否继续：

- 至少一台目标 Windows 10 或 Windows 11 设备可通过程序成功启动热点。
- 登录启动项能够在目标用户会话中访问同一网络配置。
- API 返回结果和错误能够被可靠记录。
- 选定的 .NET 发布方式可在目标设备上运行，安装包体积和依赖可接受。

如果上述条件满足，则项目进入正式实现阶段；如果目标设备受硬件、驱动或企业策略限制，则应停止部署或缩小支持范围，而不是通过提高进程权限掩盖问题。
